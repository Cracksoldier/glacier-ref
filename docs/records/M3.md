## What M3 adds

- **Format (M3.01):** [FORMAT.md](../FORMAT.md) documents schema 1: entries, manifest members, IDs, timestamps, colours, the transform convention and the order orientation → crop → size → item → group → board, limits and the compatibility policy.
- **Saving and opening (M3.02–M3.05):** File ▸ Open (Ctrl+O), Save (Ctrl+S), Save As (Ctrl+Shift+S), Board Title; command-line boards; dropped boards open. Saves run on a worker from an immutable snapshot into a `QSaveFile`, with a 512 px preview; edits made during a save stay dirty.
- **Conflicts (M3.06):** a hidden sibling lock per board; boards locked elsewhere open read-only (edit in memory, Save As only); external modification asks Save As / Replace / Cancel.
- **Links (M3.07–M3.08):** File ▸ Import as Link (Ctrl+Shift+I); relative paths where possible, rebased by every save; placeholders for missing or changed files; Board ▸ Links: Locate, Reload, Accept Changed File, Embed, Embed All, all undoable.
- **Recovery (M3.09–M3.10):** snapshots of dirty boards every 60 s at most (QSettings `recovery/intervalSeconds`, `recovery/budgetMiB`), a shared SHA-256 pool, three snapshots per board, a 2 GiB budget; at startup Recover / Open Original / Discard / Decide Later; recovered boards open dirty; closing a dirty window asks Save / Discard / Cancel.

New or extended suites:
- `tst_linkpaths`: roots (Unix, drive, UNC), platform-independent normalization, relative/absolute rules (shared ancestor below the root, Windows drives and case, UNC shares), Save As rebasing, invalid combinations.
- `tst_manifest`: round trip of every field with byte-identical rewriting; documented shape; locale independence; unreferenced assets dropped; relative links resolved against a new location; unknown members ignored; **34 rejection cases** (format, newer/older/invalid schema, IDs, UTC times, title, duplicate IDs, transforms, coordinate range, crop, missing asset, item type, group membership, nesting, empty group, digest, media type, traversal entry, asset kind, sizes, dimensions, link paths, colours, background opacity, zoom, note length, array types); malformed JSON, depth pre-scan, manifest size and item limits; migration registry (upgrade, failing step, newer version).
- `tst_boardserializer`: save → load into a fresh store equals the board, including a linked asset (A03); archive layout (manifest first, shared asset stored once, stored vs deflated, preview); optional or corrupt preview and unknown entries; changed and missing links reported, never accepted; a save with missing bytes writes nothing; **20 hostile archives** (traversal, absolute, backslash and drive names; duplicate entries; too many entries; compression bomb; uncompressed total; truncated; garbage; no manifest; tampered asset; wrong length; format and dimension mismatch; a 20000² header behind a 32×24 description; missing entry; SVG with an external reference; newer schema; oversized manifest) (A07); oversized and missing files.
- `tst_compatibility`: committed schema 1 fixtures (`tests/fixtures/boards`: every feature, a relative link, a refused schema 2 board) load identically, pixels included, and survive saving again (A03, M3.11).
- `tst_atomicsave`: a simulated full disk at the first byte, in the manifest, in the middle and at the last byte of the central directory keeps the previous board byte-identical, with no temporary files left; a failed first save leaves no file; an unwritable folder; a helper process **killed in the middle of a save** leaves the original intact; fingerprints detect external modification (A05, M3.12).
- `tst_documentlock`: hidden sibling lock released on close; a second writer in the same process and a helper process get read-only; the lock of a killed process is taken over; a lock from another host is never taken over until explicitly removed; an unwritable folder is read-only.
- `tst_recovery`: a helper process writes snapshots and is killed; **named and unnamed boards** are offered with their latest complete snapshot and load into a fresh store; running sessions are never offered; an interrupted (asset missing from the pool) and a damaged newer snapshot fall back to the last complete one; three snapshots per board; pool assets shared and collected; the budget never drops the newest snapshot of an open board (A06).
- `tst_commandcontroller`: a save that completes after another edit leaves it dirty (undo returns to clean); undo past the saved state plus a new edit makes it unreachable; undo-limit drops shift the base state; never-clean and history reset.
- `tst_links`: Import as Link stores the path; Save As into a deeper folder rebases `../pics/…` to `../../pics/…`; a moved file shows a placeholder of the same size and is located (undo restores the placeholder); a changed file is flagged on open and on reload and only accepted explicitly (the width stays, the aspect ratio follows the new file; undoable); embedding removes the dependency; a linked import of bytes already embedded stays embedded (A04).
- `tst_mainwindow`: 32 spec shortcuts; save/open round trip with the title defaulting to the file name; Open activates the window that shows the board, reuses an empty window and gives a second window read-only access; a failed open closes the window opened for it; edits during an asynchronous save stay dirty; failed saves keep changes and explain why; external modification is not overwritten silently; close prompt (Cancel keeps the window, Discard closes it); Ctrl+S while editing a note commits the note and saves; board title is undoable; recovery snapshots follow the board and are removed by Save and by Discard; a recovered board opens dirty, linked to its original, and replaces the old recovery data; the recovery dialog.

Bugs found and fixed by these tests:
- miniz 3.1.2 leaks its deflate state when a write fails during compression (ASan). `ZipWriter` now uses a tracking allocator; the vendored source is unchanged ([DEPENDENCIES.md](../DEPENDENCIES.md)).
- Snapshot folders keyed by the board's document ID would have let two windows showing the same file delete each other's recovery data; they are keyed per window.

## Known limitations

- Recovery settings have no UI yet (M4.02 Preferences); they are QSettings keys.
- Stale lock detection on network shares relies on host names: two machines with the same host name sharing a folder can't tell each other's locks apart.
- Size and modification time detect external changes; a program that rewrites a board with the same size within the file system's timestamp resolution is not detected.
- On file systems where hard links between the session store and the recovery pool are not possible, assets are copied once into the pool.
- Linked files are read in full when a board is opened (to compare digests); very large linked sets open more slowly than embedded ones.
- Note heights are computed with the system font; another platform's font metrics can produce slightly different heights until the note is edited.
- Always on Top remains guidance-only on Wayland (M4.03).
